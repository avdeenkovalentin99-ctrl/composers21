## Вероятный технический механизм

`scripts/import-composers.mjs:429–512` собирает биографию с исходного сайта. Корень поиска может быть `.t-records`, `#allrecords` или вообще `body`; внутри ищутся не только абзацы биографии, но и `.t-descr`, `.t-card__descr`, `.js-feed-post` и другие общие элементы. Фильтр на строке 469 удаляет только описание текущего человека, а не описания посторонних карточек.

Повторяемая фраза в точности совпадает с полем `posts[2].descr` записи «Ольга Иванова» в сохранённом `tmp_data/composers_raw.json`: 98 символов. Этот JSON находится в Git с исходного коммита `7668e61` от 17 апреля 2026 19:06:18 +03:00 и после не менялся. Совпадение подтверждено по сохранённым исходным данным, а не по памяти или внешнему сайту. Нынешний `participants.generated.ts:280` также использует её как описание Ольги Ивановой.

Наиболее вероятно, что скрипт захватил её из общего блока исходной страницы и приклеил к биографиям других людей. Это вывод из кода и характера повторения; точный DOM исходных страниц на 18 апреля в этой проверке не восстановлен. В сохранённых `tmp_scrape/*.html` фразы не обнаружено. Фраза не зашита в импортёр константой. Сам файл импортёра в `d25cf33` и нынешнем HEAD побайтно одинаков: Git blob `c99e1aa7cee69a62ffec26a23fc699f8625c56f5`.

Для восстановления нужно сравнивать каждый повреждённый блок с последней корректной версией и исходными авторскими материалами; пересоздание данных из нынешнего composers_bios.md само по себе повтор не устранит.
